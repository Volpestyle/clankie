# VUH-2238: separate remote queue, execution and observation costs

The [deployed attribution trace](../2026-10-13-vuh-2238-issue-attribution/README.md) identifies remote proof as the expensive dependency: p95 1683 ms versus total attribution 1692 ms. PC census also spikes to p95 3449 ms. This change measures the remote internals; it does not implement a behavioral fix.

At the lead-cleared sites, the caller logs its existing shell await as `remote.proof.timings`. The Windows relay records monotonic enqueue-to-dequeue residence and existing script execution, sending content-free diagnostics matched to the existing command ID. The existing process probe emits timings for binding, pane process, agent, kernel table, launchers, native process enrichment, listeners, ancestry and markers. First and last reads, proof selection and revalidation are untouched.

Diagnostic frames do not settle observations, clear timers, create streams or change result bytes. Unknown IDs, malformed timings and nonfinite durations are ignored; at most 18 probe steps are retained per existing command. The original frame/result, 16-command bound, coalescing, timeout and late-result fences remain. Logging contains fixed phase names, duration and outcome only; no command, output, PID, pane, path or error text. Nested timings must not be summed.

The relay bootstrap is generated by the Mac service in fleet-link.ts and sent over its existing SSH stream. A new relay launched after Mac deployment receives these changes; existing old relays work without telemetry. The probe checks for the optional telemetry method and ignores diagnostic failures, retaining its original JSON on either route. No PC update/restart or live relay steering was performed. The actual Windows emitter and five-minute comparison await lead deployment and the next live window.

Governed focused verification passed 107 cases across three files. The new transport-boundary case proves diagnostic frames cannot settle an authenticated observation, and preserves the original result bytes; existing proof/relay/project-lead cases retain their validation coverage. These local checks do not constitute Windows E2E evidence. The final relay check passed all 17 cases after the fixed phase-name allocation cleanup. Scoped format/lint passed; exact landing gate pending.
