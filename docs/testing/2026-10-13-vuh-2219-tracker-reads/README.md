# VUH-2219: repeated local tracker reads

The VUH-2216 live CPU profile on PID 92871 measured `parseStore` at 51.3 s inclusive (3.75% of 1,367 s), including 24.0 s self; `auditHash` consumed 19.3 s inclusive. Every `load()` reread and parsed/audited the whole retained file, and subscription replay parsed it again. One concrete recurring caller is `tracker-owner-loop.ts`'s five-second drain: `storeId()` followed by `list_issue_events`; owner activity also triggers drains. Reads, sync operations, mirror views and owner-ask operations share this loader.

Each backend now retains one validated snapshot. Every access still rereads the real file; only byte-for-byte identical content can reuse parsing and hash-chain validation. Any changed content receives the complete existing validation. Writes, cycle rollover and exposed mirror views isolate their store; read results and subscription events retain their existing defensive clones. Store locking, authority checks and atomic persistence are unchanged. Invalid content never falls back to an old cached result.

A read-only copy of the real tracker held 6,210,365 bytes, 58 issues, 426 item events, 244 audit entries and 244 sync commits. Both measurements used SHA-256 `35a5f62e46bcb7e45da82bf0af15d690b266f6466a5d1c5895cf7a9d950d1cd2`, with identical query results and unchanged copied bytes. Across thirty reads, excluding the cold read, old query p50/p95 was **30.56/35.82 ms**; the byte cache was **1.43/3.97 ms**. These governed copy measurements are not a live server-latency improvement claim; cold reads still validate everything.

The real file-backed regression warms reads, mutates a returned result, updates the same tracker from a separate Node process, checks subscription replay, then edits a history hash while preserving file size and restoring timestamps. Reads, store identity, subscription and writes must refuse corruption, preserve its bytes, and recover only after valid bytes are restored. The first child setup could not resolve `tsx` from the package test; the corrected service test uses its existing loader export.
